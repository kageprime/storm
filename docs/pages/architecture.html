Architecture

System architecture and data flow

High-Level Architecture

Browser (React + Tailwind) | | HTTP + SSE v Hono Backend (Node.js) | | @opencode-ai/sdk v opencode server (embedded) | | opencode/deepseek-v4-flash-free v Free DeepSeek Model | +----+----+ | | SQLite Sandbox Directory (users, (1 per project, goals) git repo or empty)

Agent Loop Flow

User: "Build a REST API for a todo app" | v [Goal submitted] --> POST /api/projects/:id/goals | v [Planner] --> Send goal to opencode with json_schema format | Returns structured sub-tasks: | [{id, description, files, depends_on}, ...] | v [User approves plan] <-- Steering point #1 (buttons + chat) | v [For each sub-task]: |--- Send sub-task to opencode via session.prompt() |--- Stream progress via SSE (tool calls, file diffs) |--- User sees real-time updates in browser +--- On completion: Steering point #2 (continue/redo/stop) | v [Goal complete] --> Summary to user

Key Design Decisions

Why Hono?

Lightweight, fast, TypeScript-native. Same runtime as opencode (Node.js). Built-in CORS, middleware, and excellent developer experience.

Why sql.js?

Pure JavaScript SQLite — no native compilation needed. Zero-config database that persists to a single file. Perfect for single-server deployment.

Why SDK over CLI?

The @opencode-ai/sdk provides programmatic control over opencode — create sessions, send prompts, stream events — without shelling out to a subprocess.

Why SSE over WebSocket?

SSE is simpler, native in browsers (EventSource), works through proxies, and is a natural fit for the unidirectional streaming our agent loop needs.

Why Sandboxed Directories?

Each project gets an isolated filesystem. opencode operates only within that directory. MVP uses simple dirs; Docker containers planned for production isolation.

Why Free DeepSeek?

opencode/deepseek-v4-flash-free is built into opencode — no API key, no costs, no rate limits. Powers the entire agent loop at zero operational expense.
