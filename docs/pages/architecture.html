Key Design Decisions

Why Hono?

Lightweight, fast, TypeScript-native. Same runtime as opencode (Node.js). Built-in CORS, middleware, and excellent developer experience.

Why sql.js?

Pure JavaScript SQLite — no native compilation needed. Zero-config database that persists to a single file. Perfect for single-server deployment.

Why SDK + External Server?

We connect to an existing opencode server on port 4096 via createOpencodeClient — no child processes, port conflicts, or startup delays. Fresh session per step avoids context pollution.

Why SSE over WebSocket?

SSE is simpler, native in browsers (EventSource), works through proxies, and is a natural fit for the unidirectional streaming our agent loop needs.

Why Sandboxed Directories?

Each project gets an isolated filesystem. opencode operates only within that directory. MVP uses simple dirs; Docker containers planned for production isolation.

Why Free DeepSeek?

opencode/deepseek-v4-flash-free is built into opencode — no API key, no costs, no rate limits. Powers the entire agent loop at zero operational expense.

Why Message Persistence?

Every event (plan, steps, steering, user messages, errors) saves to goal_messages. Users who reconnect or refresh see full history — no state loss.

Why Files API?

Backend serves recursive file trees (skipping .git/node_modules) and file content (text or base64). Frontend renders HTML in sandboxed iframes, images inline, and code in pre blocks.

Why Dev Server Proxy?

Projects with package.json get an auto-started npm run dev process. Preview requests proxy through the backend at /api/preview/:projectId with HTML path rewriting (/assets/* → /api/preview/:projectId/assets/*) so frameworks like Vite work seamlessly.

Why authMiddleware Fix?

Missing return before c.json() left the Hono context unfinalized, causing "Context is not finalized" errors. All middleware now returns responses correctly.
